## Context

当前视觉链路已经具备本地主体检测、CLIP crop embedding、家庭类目索引和评测报告能力。真实客厅照片暴露了命名侧短板：电视机、功放、唱片机等高频客厅电子影音类目没有进入本地 taxonomy/index，而投影仪已经存在，因此相似的黑色或银色电子设备会被最近邻检索误命名为投影仪。

当前 YOLOX 主体检测是单类主体框模型，本次不改检测模型、训练数据或召回策略。变更聚焦在检测框之后的命名阶段：类目覆盖、代表图质量、embedding 索引和低置信拒识。

## Goals / Non-Goals

**Goals:**

- 补齐第一批高频家庭电子影音叶子类目，并保持 GS1 GPC-style 四级骨架和中文展示路径。
- 为新增叶子类目采集淘宝来源代表图，每个叶子类目先保留 3 张 gallery 图。
- 使用现有离线流程生成新增类目的 crop embedding，并合并到本地 household index。
- 在线命名从“单条最近邻即命名”升级为“TopK 类目聚合 + 阈值 + margin 拒识/候选”。
- 产出电子影音 hard-negative 命名评测报告，重点观察投影仪、功放、唱片机、电视盒子、播放器等相似类混淆。

**Non-Goals:**

- 不训练、不微调、不替换 YOLOX、Grounding DINO 或 OWL-ViT 主体检测模型。
- 不承诺本次把所有家庭电子产品长尾补完。
- 不引入云端 VLM 或外部在线推理作为默认命名路径。
- 不把 3 张淘宝商品图视为最终生产级覆盖；这只是第一版可验证索引。

## Decisions

1. 新增类目采用电子影音包，而不是零散补单个错误类。

   只补“功放”和“唱片机”会把错误从投影仪转移到其他相似电子设备。第一批应同时覆盖电视机、功放、AV 接收机、唱片机、书架音箱、落地音箱、有源音箱、回音壁、机顶盒、电视盒子、媒体播放器、CD/DVD/蓝光播放器和柜机空调等客厅高频物品。这样 hard-negative 评测才有意义。

2. 每个叶子类目先保留 3 张淘宝商品图。

   用户明确要求本次仍保持 3 张淘宝商品图。采集脚本应记录来源标题、URL、图片路径和 review 状态。后续如果命名准确率仍低，再扩展到真实家庭场景图和更多品牌角度。

3. 命名检索按类目聚合，而不是直接使用单条 Top1。

   单张 gallery 图质量不稳定时，直接 Top1 容易被坏样本带偏。运行时应取 entry TopK 后按 `categoryId` 聚合，计算每个类目的 best score、平均 top score、命中数量和代表样本，再输出类目级候选。

4. 命名必须支持拒识。

   当最佳类目分数低于阈值，或第一名与第二名 margin 太小，系统不得强行返回错误物品名。UI 可以展示“未知电子设备”或“可能是 A / B / C”，并保留相似索引图供用户修正。

5. 评测优先验证命名上限和相似类混淆。

   本次不优化主体检测，因此评测应包含 GT-crop/审核框命名评测，以隔离“框错”和“名错”。同时保留 app 端真实链路 smoke test，确认运行时不会静默退化。

## Risks / Trade-offs

- 3 张淘宝商品图不足以覆盖真实家庭视角 -> 先用 hard-negative 报告定位混淆，后续按错误类扩图。
- CLIP 对黑色矩形电子设备区分能力有限 -> 用类目聚合、margin 拒识和相似类阈值降低误报。
- 新增类目没有完全等价的 GS1 GPC Brick -> 使用 GPC-style 四级 lineage，并记录 project override reason。
- 淘宝图片可能含营销图、组合图或场景图 -> manifest 保留 reviewStatus 和 sourceTitle，构建报告记录主体框失败样本。
- 阈值过严会提高未知率 -> 报告同时展示 Top1、Top3、拒识率和人工可接受率，便于后续调参。
